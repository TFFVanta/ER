# v1.0 Definition of Done
- One workspace lock prevents two runtimes from operating the same state directory.
- Startup order is derived from declared dependencies and rejects cycles or missing services.
- Every service runs recovery before it starts.
- Startup failure stops and joins every service already started.
- Shutdown proceeds in reverse dependency order.
- Scheduler execution flows through agent allocation, governance, resource reservation, Autonomy Kernel execution, verification, reconciliation, and learning.
- Every selected identity is revalidated immediately before execution.
- Emergency stop blocks governance and resource admission.
- Runtime status, service health, alerts, audit events, traces, metrics, and control commands are durable.
- Cross-process CLI shutdown and emergency requests are processed by the running host.
- Runtime state is isolated by workspace ID and workspace database path.
- Simulation mode suppresses real external execution.
- Expired scheduler leases, resource reservations, and agent bindings are recovered after restart.
- Failure-injection, integration, and soak tests pass.
- Windows service stop produces a clean scheduler drain and workspace-lock release.
- A 24-hour soak has no stuck leases, reservations, assignments, unbounded memory growth, or missing audit sequence.
